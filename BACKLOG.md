## 🎯 Ближайшие (1–2 спринта)

- [ ] **Подсветка `[N]` в тексте ответа AI**
      Сейчас источники показаны отдельным блоком под сообщением, но
      `[1]`, `[2]` в тексте — просто текст. Сделать: подсветка `[N]`
      тапабельна является ссылкой на источник, тап → скролл к соответствующему источнику (или
      раскрытие блока с подсветкой).

- [ ] **Суффикс `(частично)` в sources `document_chat`**
      README `document_chat`: обрезанный документ помечается
      `" (частично)"` в имени. Пометить в UI — иконкой или
      серым цветом, с тултипом «Документ обрезан по лимиту контекста».

- [ ] **Переименование `ChatStreamCompleted.agentId` → `model`**
      Сейчас поле называется `agentId`, но фактически содержит `model`
      из ответа сервера (`rag/<uuid>` для RAG, `epoz` для обычных).
      Убрать путаницу на уровне типа: переименовать в `model`,
      добавить `agentId` отдельно, если понадобится.

- [ ] **Retry для неотвеченных сообщений**
      Пользователь отправил сообщение, сеть упала, `SnackBar` исчез —
      но сообщение осталось в истории как «отправленное», без ответа.
      Требует: `Message.deliveryStatus` (`sent`/`pending`/`failed`),
      визуальный индикатор в `MessageBubble` («не отправлено»),
      кнопка «повторить» → `ChatNotifier.retryMessage(messageId)`.

- [ ] **Индикатор долгой обработки файла (`document_chat`)**
      MinerU обрабатывает 30–120 сек (`MINERU_TIMEOUT_SECONDS=600`).
      Сейчас пользователь видит спиннер и не понимает — идёт работа
      или всё зависло. Требует: текст «Обработка документа… Это может
      занять минуту», таймер, опционально «Отменить».

- [ ] **Проверка `content-type` в `postStream`**
      Если сервер вернёт `200 application/json` вместо SSE — парсер
      попытается читать как SSE и выдаст мусор. Проверять
      `response.headers['content-type']` в `AppHttpClient.postStream`.

- [ ] **Тест на `event: error` в SSE-стриме**
      `_parseErrorEvent` обрабатывает оба варианта: `error` (обычные
      агенты, README `document_chat`: `sequence_number: 9999`)
      и `response.error` (`agentic_rag`). Есть тест на `response.error`.
      Нет теста на старый `event: error`. Добавить.

- [ ] **Индикатор частичных ошибок в `ChatHistoryDrawer`**
      Сейчас если один агент упал — его чаты просто не показываются,
      без объяснений. Различать «всё упало» и «часть упала»,
      баннер «Часть чатов не загружена» + кнопка «Повторить».
      Требует: расширения `chatsProvider`.

- [ ] **`ChatRepository.getRoute` — переопределить `userMessage` для 404/502/503**
      Сейчас любой 404 → «Ресурс не найден». Для `/route` 404 может
      значить «роутер не смог», 502 — «мастер недоступен». Не путать.

- [ ] **Улучшить сообщения `ServerException` при 401**
      Сейчас 401 всегда «Не авторизован. Пожалуйста, войдите заново».
      Но 401 может прийти от nginx/техработ — сообщение врёт.
      После ввода Keycloak — пересмотреть.
